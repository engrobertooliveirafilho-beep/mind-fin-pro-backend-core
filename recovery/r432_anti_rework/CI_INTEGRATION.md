# MIND Anti-Retrabalho — CI integration
The GitHub Actions job `anti-rework` runs 11 isolated unit tests and checks `.mind/anti_rework/candidate.json` against `.mind/anti_rework/inventory.json`. If either file is missing, job FAILS CLOSED. Do not create an empty inventory to circumvent the check. Inventory must be verified from authoritative Drive/GitHub provenance. `ALLOW_STAGING` is **not** permission to merge, deploy, or trade. `REUSE` means exact byte-hash match only, not semantic equivalence.

**Important limitations:** The workflow runs on the audit branch and PRs. It does not by itself make the check required for merging: repository branch protection / rulesets must require job `anti-rework`. The `--source-verified` flag is intentionally NOT supplied by CI: authority cannot be established from a self-asserted candidate file. Thus genuinely new candidates BLOCK in this workflow until an independent, trusted authority verification mechanism is wired in. The workflow has no broker credentials, live orders, paid APIs, or Drive mutation. No production integration was performed.
